## 1. 实验背景与 Baseline 分析

本实验旨在探究在奖励稀疏且奖励函数设计可能存在缺陷（Reward Hacking 风险）的环境下，PPO 与 GRPO 算法的微调表现。实验选取了 `curriculum-v7.1` 作为 Baseline。

**Baseline (curriculum-v7.1, PPO) 表现：**
- **成功率 (Success Rate):** 0.050 +/- 0.045。模型偶尔能完成任务。
- **平均回报 (Mean Return):** 243.9 +/- 21.8。
- **动作平滑度 (Action Smoothness):** 26280.7 +/- 3403.6。

Baseline 表明，即使经过课程学习预训练，模型在 Door 任务上的成功率依然极低（5%），这印证了 HumanoidBench 中该任务奖励信号稀疏且环境复杂的特性。

---

## 2. Phase 1：原始环境微调分析

在此阶段，我们在原始环境（包含 Dense Reward Shaping）下分别微调 PPO (`ft_ppo_v2`) 和 GRPO (`ft_grpo_v2`)。

### 2.1 奖励与成功率的严重背离 (Reward Hacking 现象)
| 模型选择标准 | 算法       | 成功率          | 平均奖励  | 轨迹长度  | 动作平滑度   |
| ------ | -------- | ------------ | ----- | ----- | ------- |
| -      | Baseline | 5.0% (±4.5%) | 243.9 | 731.0 | 26280.7 |
| 最高成功率  | PPO      | 1.0% (±2.0%) | 483.0 | 975.0 | 24854.3 |
| 最高成功率  | GRPO     | 2.0% (±4.0%) | 222.3 | 728.6 | 25769.1 |
| 最高奖励   | PPO      | 0.0% (±0.0%) | 427.1 | 910.6 | 26304.5 |
| 最高奖励   | GRPO     | 1.0% (±2.0%) | 209.5 | 769.8 | 28650.9 |

通过对比 WandB 图表 `eval/mean_reward` 和 `eval/success_rate`，以及最终评估表格，我们观察到了显著的现象：

- **PPO 的“高分低能” (Reward Hacking):**
	- **图表观察:** 在 `eval/mean_reward` 图中，PPO (橙色线) 呈现出明显的上升趋势，从初始的 ~200 一路攀升至 ~500。然而，在 `eval/success_rate` 图中，PPO 的成功率始终在 0.1 以下波动，甚至在训练后期趋近于 0。
	- **数据验证:** 以奖励为基准选择的 PPO 模型 (`model_23000000_steps`)，其 Mean Return 高达 **427.1** (远超 Baseline 的 243.9)，但 Success Rate 降为 **0.000**。
	- **分析:** 这表明 PPO 严重过拟合了环境中的 Dense Reward（如 `door_openness_reward` 或距离奖励）。模型学会了通过“刷分”行为（例如在门附近反复摩擦或保持特定姿态以获取密集奖励）来最大化回报，而不是真正完成“推开门并通过”这一稀疏目标。这也侧面证实了引用文献中提到的“bench 本身的奖励设计有问题，相当稀疏且易被利用”。

- **GRPO 的一致性与保守性:**
	- **图表观察:** 在 `eval/mean_reward` 图中，GRPO (蓝色线) 始终维持在 ~200 的水平，没有像 PPO 那样大幅上升。
	- **数据验证:** GRPO 的 Best Model (以成功率为基准) Mean Return 为 **222.3**，与 Baseline (243.9) 非常接近；Success Rate 为 **0.020**，也与 Baseline (0.050) 处于同一数量级（考虑到方差）。
	- **分析:** GRPO 表现出极强的一致性。它没有被有缺陷的 Dense Reward 带偏，没有发生严重的 Reward Hacking。其策略表现与预训练模型高度相似，说明 GRPO 在优化过程中对奖励信号的利用更加“诚实”，或者说其 Group Relative 机制抑制了对局部 Dense Reward 的过度贪婪。


### 2.2 动作平滑度 (Action Smoothness) 分析
![[W&B Chart 2026_7_14 21_25_56.png]]

动作平滑度定义为 $\sum ||a_t - a_{t-1}||^2$，数值越低代表动作越平滑、质量越高。

- **图表观察:** 在 `behavior/action_smoothness` 图中，差异极为显著。
	- **PPO (橙色线):** 数值稳定在 **30,000 - 40,000** 之间。
	- **GRPO (蓝色线):** 数值剧烈波动，且始终维持在 **80,000 - 120,000** 的高位，是 PPO 的 3 倍左右。
- **表格数据:** 尽管表格中的 Eval Action Smoothness 差异较小（PPO ~24,854 vs GRPO ~25,769），但这可能是因为 Eval 时的策略经过了一定收敛。但在训练过程 (Behavior) 中，GRPO 的动作质量明显较低。
- **结论:** GRPO 在微调过程中产生的动作极其剧烈、抖动频繁。这可能是因为 GRPO 的采样机制或优势估计导致策略在探索时更加激进，或者为了应对稀疏奖励而采取了高频震荡的探索策略。这也解释了为什么 GRPO 的 `eval/mean_ep_length` (蓝色线) 波动较大且经常低于 PPO (橙色线达到 1000 max length)，因为剧烈的动作可能导致机器人更快摔倒或触发终止条件。

## 3. Phase 2：极端稀疏奖励分析

在此阶段，我们移除了所有 Dense Reward，仅使用 Ground Truth (`robot_x > 0.8`) 作为二值奖励 (Success = 1, else 0)。这是为了模拟现实世界中极度稀疏的奖励环境。

| 算法       | 成功率          | 平均奖励  | 轨迹长度  | 动作平滑度   |
| -------- | ------------ | ----- | ----- | ------- |
| Baseline | 5.0% (±4.5%) | 243.9 | 731.0 | 26280.7 |
| PPO      | 0.0% (±0.0%) | 126.1 | 628.0 | 26143.2 |
| GRPO     | 1.0% (±2.0%) | 194.5 | 667.6 | 24957.9 |

### 3.1 PPO 的彻底崩溃

- **数据:** PPO (`ft_ppo_v3`) 的 Success Rate 为 **0.000**，Mean Return 降至 **126.1**。
- **分析:** 相比于 Baseline (Return 243.9)，PPO 的表现大幅倒退。这说明 Phase 1 中 PPO 学到的策略完全依赖于 Dense Reward 的引导。一旦移除这些“拐杖”，模型完全不知道如何行动，甚至表现不如随机或初始策略。这进一步证实了 Phase 1 中 PPO 的“高分”完全是虚假的。

### 3.2 GRPO 的鲁棒性 (Robustness)

- **数据:** GRPO (`ft_grpo_v3`) 的 Success Rate 为 **0.010**，Mean Return 为 **194.5**。
- **分析:**
	- 虽然成功率依然很低（任务本身太难），但 GRPO 的 Mean Return (194.5) 与 Baseline (243.9) 以及 Phase 1 的 GRPO (222.3) 保持在**相近的水平**。
	- 相比之下，PPO 从 243 跌到了 126，而 GRPO 仅从 243 跌到 194（甚至 Phase 1 的 GRPO 只有 222）。
	- **结论:** 这有力地证明了 **GRPO 应对稀疏奖励的能力优于 PPO**。GRPO 没有过度拟合 Phase 1 中的 Dense Reward 模式，因此当环境变为极端稀疏奖励时，其策略没有发生严重的性能偏移 (Performance Shift)。GRPO 的优化目标（基于组内相对优势）可能在缺乏绝对奖励标尺时，比 PPO 的 GAE 估计更稳定，或者至少不容易产生错误的梯度方向。

## 4. 综合结论与讨论

1.  **奖励函数缺陷与 PPO 的局限性:** HumanoidBench 的 Door 任务奖励设计存在严重问题。PPO 算法极易陷入 Reward Hacking，导致训练曲线上的 Reward 飙升（~500），但实际任务成功率（Success Rate）反而下降至 0。在移除辅助奖励后，PPO 策略完全失效。
2.  **GRPO 的稳定性与稀疏奖励适应性:** GRPO 表现出显著的“抗干扰”能力。
    *   在 Phase 1 (有缺陷的 Dense Reward) 中，GRPO 没有被带偏，保持了与 Baseline 相近的 Reward 和 Success 水平。
    *   在 Phase 2 (极端稀疏 Reward) 中，GRPO 依然保持了接近 Baseline 的 Return 水平，证明其学到的策略更具通用性，对奖励稀疏性的鲁棒度更高。
3. **GRPO的动态平滑度特征**：实验观察到GRPO在训练过程中动作平滑度远高于PPO（约100,000 vs. 25,000），但在评估阶段其平滑度（~25,769）与PPO（~24,854）相当，且在Phase 2中优于PPO。这一差异表明，GRPO训练时的高动作方差主要源于其群体比较机制驱动的主动探索，而非策略本身的不稳定性。评估时的低平滑度则证明GRPO能有效收敛至平稳策略。这一发现与GRPO的保守优化特性一致，也为在稀疏奖励任务中使用GRPO提供了实证支持。

## 5. 存在的问题及后续方向
目前最大的挑战在于**基线模型（Baseline）过于薄弱**，这直接削弱了微调（Fine-tuning）对比实验的说服力。

- **问题现状：** `curriculum-v7.1` 基线模型的成功率仅为 **5.0%**。在 Phase 1 和 Phase 2 的微调后，PPO 和 GRPO 的成功率甚至在 **0.0% - 2.0%** 之间徘徊。这表明微调并没有提升策略性能，反而可能因为误导性奖励信号导致了灾难性遗忘（Catastrophic Forgetting）或陷入局部最优。
- **研究目标的冲突：** 我原本的核心研究问题是：“在稀疏奖励环境下，从非零成功率的基线策略开始微调，GRPO 是否优于 PPO？”
    - **选项 A（坚持当前环境）：** Door 任务在稀疏奖励下极难。即使重新从头训练基线，可能依然只能得到 5% 的成功率，导致我们依然没有强有力的起点来进行微调对比。
    - **选项 B（切换到更简单的环境）：** 这将违背研究的初衷（即研究复杂移动操作任务在稀疏奖励下的表现）。如果任务太简单或奖励稠密，PPO 和 GRPO 都能轻松解决，对比将变得毫无意义。
- **请求指导：** 我不确定如何在符合研究约束（稀疏奖励、复杂任务）的前提下，获得一个有效的“非零成功率”基线。**我应该：**
    1. **调整研究重心？**（例如：不再强调“提高成功率”，而是转向研究“GRPO 在有缺陷奖励环境下的抗干扰能力/鲁棒性”，因为数据显示 GRPO 没有像 PPO 那样进行 Reward Hacking）。
    2. **更换初始化方法？**（例如：使用模仿学习 Imitation Learning 从人类演示中获取强基线，然后再用 RL 微调）。
    3. **更换任务？**（在 HumanoidBench 中寻找另一个既需要长程规划、又稍微容易一点的移动操作任务，例如 Object Pushing）。
